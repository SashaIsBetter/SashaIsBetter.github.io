19:T694,<h2>1. Definition</h2>
<p><strong>VDSP (Verified Distillation with Self Practice)</strong> is a way to improve a small model without human labels, paid compute, or private data. Every night it does three things:</p>
<ol>
<li>It gathers candidate training examples from two places: stronger <em>teacher</em> models, and the student itself.</li>
<li>It keeps only the candidates that pass an automatic check.</li>
<li>It trains on those, and the new model is adopted only if it beats the current one on a held-out test.</li>
</ol>
<p>Two ideas give the method its name. <strong>Verified distillation:</strong> the student copies the teachers, but only on answers that were checked. <strong>Self practice:</strong> the student also learns from its own attempts that passed the same checks.</p>
<div class="defn">
<p class="defn-label">Definition</p>
<p>Let θ<sub>t</sub> be the student on night t, T a set of teacher models, X a pool of tasks, and V(x, y) ∈ {0, 1} a verifier that accepts answer y to task x only when it can check it. A VDSP night builds</p>
<p class="eq">D_t = { (x, y) : x ∈ X,  y ~ T(x) ∪ θ_t(x),  V(x, y) = 1 }
θ'   = LoRA-train(θ_t, D_t ∪ D_&lt;t)
θ_t+1 = θ'   if  gained − lost ≥ δ  and  sign-test p ≤ 0.15  and the agent check passes
        θ_t  otherwise</p>
<p>where gained and lost count the held-out problems (never in X) that θ' newly solves and newly breaks relative to θ<sub>t</sub>, and δ is the required net gain (we use δ = 3 of 88 problems).</p>
</div><p>In words: a teacher&#39;s answer is trusted no more than the student&#39;s. A wrong answer, whoever wrote it, never becomes training data. A worse model never ships.</p>

35:Ta3f,<h2>2. Why this design</h2>
<p>Noetic 1.0 is a 9-billion-parameter hybrid model (Gated DeltaNet plus attention layers) running in 4-bit on a 16 GB MacBook Air. It can&#39;t be made smarter by scale. It <em>can</em> be taught better habits on the kinds of problems its users bring. Our constraints shaped every choice:</p>
<ul>
<li><strong>No money.</strong> Teachers are reached only through NVIDIA&#39;s free tier: DeepSeek V4.1 Flash, GLM 5.3 and Kimi K3, all open-weight. One account allows about 35 requests a minute and 950 a day, shared by all teachers.</li>
<li><strong>No private data.</strong> Training uses public benchmark-style problems and tasks the teachers invent. Conversations in the app never leave the Mac.</li>
<li><strong>No humans in the loop.</strong> If nobody grades the data, the grader must be code.</li>
<li><strong>Overnight only.</strong> Everything has to start, finish and decide by 06:00, on a laptop with the lid open.</li>
</ul>
<p>Plain distillation fails one of these on its own: teachers are often wrong, and a small student copies their mistakes as faithfully as their insights. Plain self-training fails another: a 9B model&#39;s own outputs are mostly what it already knows. VDSP uses both sources and puts the same gate in front of each.</p>

<p>Four streams feed the verifier each night. The shares below are what collection <em>asks for</em> (the <code>MIX</code> in <code>distill_free.py</code>). Section 5 shows what actually survives.</p>

4b:T10c5,<p>Scoring each model with one number on 88 problems cannot separate a real gain from luck: at 85% accuracy one score has a standard error near 4 points, and a typical night flips about 8 problems each way. So the gate compares the two models problem by problem. It requires a net gain of at least 3, a sign test over the problems that changed (p ≤ 0.15), and no kind of problem (math, code, puzzles) losing more than 2. Night 2 would have shown 0 gained and 9 lost. A rejected night costs nothing: its verified data stays in the pool and adds to the next night&#39;s training.</p>
<p><strong>The adapter is scored and shipped as it runs, not merged.</strong> Merging a LoRA adapter into 4-bit weights re-quantizes every adapted weight, which can round a small adapter away and adds noise to the base. Night 2&#39;s merged model lost 9 problems and gained none; the same adapter run unmerged on top of the same 4-bit weights passed all 27 problems we scored before stopping that check early, including 7 of those 9. So models are now evaluated and adopted as the original weights plus the adapter, and the app applies the adapter at load time.</p>

<h2>8. Related work</h2>
<p>VDSP combines well-known pieces; the combination and the constraints are what&#39;s new to us.</p>
<ul>
<li><strong>Knowledge distillation</strong> (Hinton et al., 2015) trains a student on a teacher&#39;s outputs. VDSP distils from sampled answers, not logits, and filters them first.</li>
<li><strong>Rejection-sampling fine-tuning</strong> (Yuan et al., 2023) keeps only correct samples from a model for training. VDSP applies the same filter to teacher and student samples alike.</li>
<li><strong>STaR and ReST-EM</strong> iterate generate → filter → train on a model&#39;s own outputs. VDSP&#39;s self practice is this loop, run alongside distillation each night.</li>
<li><strong>Verifiable-reward RL</strong> uses the same checkers as rewards. VDSP uses them only as filters, which is far cheaper on a laptop. Preference pairs built from Noetic&#39;s passing and failing attempts are the natural next step.</li>
</ul>
<h2>9. Limitations and next steps</h2>
<ul>
<li><strong>Verification narrows the data.</strong> Anything without a checker, like style, judgement or open questions, is under-represented or only weakly filtered.</li>
<li><strong>Fixed datasets run out.</strong> Code collapsed on night 3 because the public code set was used up, not because the checks failed. Invented tasks now refill it, but the pool grows only as fast as the teachers invent.</li>
<li><strong>Small held-out set.</strong> Even compared problem by problem, 88 problems detect only fairly large changes, and each extra problem costs about 0.85 minutes of scoring on a laptop.</li>
<li><strong>Free-tier limits</strong> cap a night at about 950 teacher requests per account.</li>
</ul>
