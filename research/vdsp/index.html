VDSP: Verified Distillation with Self Practice

Sasha Babenkov and the NoeticAI team · Oct 10, 2026

VDSP is a nightly training loop for a 9B model that lives on a laptop. Free open-weight teachers and the model itself produce candidate examples; an automatic verifier keeps only the ones it can prove correct; a LoRA adapter is trained on that verified set; and the result replaces the current model only if it scores higher on problems it has never seen. This paper defines the method, shows how each part works, and reports honestly on the first three nights.

1. Definition

VDSP (Verified Distillation with Self Practice) is a way to improve a small model without human labels, paid compute, or private data. Every night it does three things:

  1. It gathers candidate training examples from two places: stronger teacher models, and the student itself.
  2. It keeps only the candidates that pass an automatic check.
  3. It trains on those, and the new model is adopted only if it beats the current one on a held-out test.

Two ideas give the method its name. Verified distillation: the student copies the teachers, but only on answers that were checked. Self practice: the student also learns from its own attempts that passed the same checks.

Definition

Let θt be the student on night t, T a set of teacher models, X a pool of tasks, and V(x, y) ∈ {0, 1} a verifier that accepts answer y to task x only when it can check it. A VDSP night builds

D_t = { (x, y) : x ∈ X, y ~ T(x) ∪ θ_t(x), V(x, y) = 1 } θ' = LoRA-train(θ_t, D_t ∪ D_<t) θ_t+1 = θ' if gained − lost ≥ δ and sign-test p ≤ 0.15 and the agent check passes θ_t otherwise

where gained and lost count the held-out problems (never in X) that θ' newly solves and newly breaks relative to θt, and δ is the required net gain (we use δ = 3 of 88 problems).

In words: a teacher's answer is trusted no more than the student's. A wrong answer, whoever wrote it, never becomes training data. A worse model never ships.

2. Why this design

Noetic 1.0 is a 9-billion-parameter hybrid model (Gated DeltaNet plus attention layers) running in 4-bit on a 16 GB MacBook Air. It can't be made smarter by scale. It can be taught better habits on the kinds of problems its users bring. Our constraints shaped every choice:

  • No money. Teachers are reached only through NVIDIA's free tier: DeepSeek V4.1 Flash, GLM 5.3 and Kimi K3, all open-weight. One account allows about 35 requests a minute and 950 a day, shared by all teachers.
  • No private data. Training uses public benchmark-style problems and tasks the teachers invent. Conversations in the app never leave the Mac.
  • No humans in the loop. If nobody grades the data, the grader must be code.
  • Overnight only. Everything has to start, finish and decide by 06:00, on a laptop with the lid open.

Plain distillation fails one of these on its own: teachers are often wrong, and a small student copies their mistakes as faithfully as their insights. Plain self-training fails another: a 9B model's own outputs are mostly what it already knows. VDSP uses both sources and puts the same gate in front of each.

3. Where candidates come from

Four streams feed the verifier each night. The shares below are what collection asks for (the MIX in distill_free.py). Section 5 shows what actually survives.

Stream Requested share What it is
Math 34% Word problems with a known numeric answer
Code 26% Functions with unit tests
General 22% Explanations and writing, filtered for quality
Agent sessions 7% Multi-step coding sessions using Noetic's own tools in a sandbox
Invented tasks 6% Teachers write a new task, its tests and a reference solution
Gold bank 5% Hand-checked problems with exact answers

Self practice runs on the Mac's GPU while the teachers are busy. Noetic tries the invented tasks and the gold bank several times each, and only its passing attempts are kept. This is expert iteration, in the line of STaR (Zelikman et al., 2022) and ReST-EM (Singh et al., 2023), but run in the gaps of a distillation night rather than as a separate stage.

4. Verification

Verification is the whole method. Each check either proves an answer right or throws it away.

Candidate Accepted only if
Math The final number equals the gold answer
Code Every unit test passes in a sandbox with no network
Agent session Hidden tests pass on the files it wrote, and it ran code itself along the way
Invented task Its own reference solution passes its own tests
Any answer Reasoning under the length budget, no garbled text, exactly one final code block for code

The last row matters more than we expected. Teachers pass on habits along with answers. If a correct answer comes with 5,000 characters of circling, the student learns to circle. So length and form are part of "verified".

Invented tasks get one extra gate: the teacher's own reference solution must pass the tests the same teacher wrote. A task that can't pass its own tests is thrown away before any student ever sees it.

5. A night in practice

tonight.sh --until 06:00 runs the whole night. It works backwards from the hard stop: the last three hours are kept for training and deciding, and the final 100 minutes of those go to fusing the adapter, scoring it on 88 problems and running the agent check. Collection gets whatever time is left. Collection also stops early if the day's free requests run out.

Collection runs on two Macs, each assigned a different half of the task pool, so their requests never overlap. Their verified examples merge through the git repository, and each Mac trains on the union.

The comparison between requested and kept is the most useful number in this paper. Code was 26% of what we asked for, but under 1% of what was kept on night 3. Our first guess was that the checks had become too strict. The logs said otherwise: teachers passed 67% of code tasks, but each Mac's half of MBPP is only about 245 problems, and the first night used nearly all of them. By night 3 there was one left. The fix uses the method itself: every task a teacher invents and verifies is now also asked as a plain code task, and these tasks are never split between the Macs. That refilled the code pool from 1 to 113 problems, and it grows by about 60 a night.

6. Training and adoption

The student is trained with a rank-8 LoRA on 8 layers, using 3,072-token sequences and a learning rate of 2 × 10⁻⁵. The loss covers only the assistant's tokens. System prompts are dropped for teacher and self-practice examples, so the student learns the reasoning rather than the instructions. Training the hybrid model in 16 GB needed chunked Gated-DeltaNet and loss kernels; that is covered in the companion paper. The same loop can also train on a PC GPU and convert the adapter for the Mac.

Scoring each model with one number on 88 problems cannot separate a real gain from luck: at 85% accuracy one score has a standard error near 4 points, and a typical night flips about 8 problems each way. So the gate compares the two models problem by problem. It requires a net gain of at least 3, a sign test over the problems that changed (p ≤ 0.15), and no kind of problem (math, code, puzzles) losing more than 2. Night 2 would have shown 0 gained and 9 lost. A rejected night costs nothing: its verified data stays in the pool and adds to the next night's training.

The adapter is scored and shipped as it runs, not merged. Merging a LoRA adapter into 4-bit weights re-quantizes every adapted weight, which can round a small adapter away and adds noise to the base. Night 2's merged model lost 9 problems and gained none; the same adapter run unmerged on top of the same 4-bit weights passed all 27 problems we scored before stopping that check early, including 7 of those 9. So models are now evaluated and adopted as the original weights plus the adapter, and the app applies the adapter at load time.

7. Results so far

So far VDSP has produced data, not a better model. We report it as it is.

Night Benchmark Current Candidate Outcome
Oct 7 none none none Collection only. The first training attempt ran out of memory.
Oct 8 44-problem bank 44 / 44 35 / 44 Not adopted. The merged model lost 9 problems and gained none. The same adapter unmerged passed all 27 problems checked before the test was stopped.
Oct 9 88 held-out none none Collection succeeded. Scoring crashed on a missing package before training; now fixed.

The night-2 result taught us two things about the measurement, not the model. A test the base model already aces can't show progress, and a strict grader penalises answers that are right but formatted differently. We replaced the bank with 88 held-out problems (48 GSM8K, 32 HumanEval, 8 puzzles) and fixed answer extraction. The first full night with the new evaluation trains on all 2,216 verified examples.

8. Related work

VDSP combines well-known pieces; the combination and the constraints are what's new to us.

  • Knowledge distillation (Hinton et al., 2015) trains a student on a teacher's outputs. VDSP distils from sampled answers, not logits, and filters them first.
  • Rejection-sampling fine-tuning (Yuan et al., 2023) keeps only correct samples from a model for training. VDSP applies the same filter to teacher and student samples alike.
  • STaR and ReST-EM iterate generate → filter → train on a model's own outputs. VDSP's self practice is this loop, run alongside distillation each night.
  • Verifiable-reward RL uses the same checkers as rewards. VDSP uses them only as filters, which is far cheaper on a laptop. Preference pairs built from Noetic's passing and failing attempts are the natural next step.

9. Limitations and next steps

  • Verification narrows the data. Anything without a checker, like style, judgement or open questions, is under-represented or only weakly filtered.
  • Fixed datasets run out. Code collapsed on night 3 because the public code set was used up, not because the checks failed. Invented tasks now refill it, but the pool grows only as fast as the teachers invent.
  • Small held-out set. Even compared problem by problem, 88 problems detect only fairly large changes, and each extra problem costs about 0.85 minutes of scoring on a laptop.
  • Free-tier limits cap a night at about 950 teacher requests per account.

Next: the first full training night on the 88-problem evaluation, training on the PC GPU while the Macs collect, and preference pairs from Noetic's own correct and incorrect attempts.
